# Replay this experiment

This folder is an offline research replay, not a new Timegrapher estimator.
Python 3.11+ and FFmpeg/FFprobe are required; the original decoding used FFmpeg
7.1.5. Install `requirements.txt` in a virtual environment. The pinned NumPy and
SciPy versions match the original endpoint analysis.

Raw originals are contributor-retained; public archive links are pending in
`../manifest.json`. Supply those files locally. The replay checks their SHA-256
hashes before analysis, and outputs into a separate directory:

```sh
python -m venv /tmp/optical-venv
. /tmp/optical-venv/bin/activate
pip install -r requirements.txt
python reproduce.py \
  --video /path/to/IMG_5824.MOV \
  --mic /path/to/audio-001.wav \
  --timegrapher /path/to/timegrapher \
  --output /tmp/optical-replay
```

Omit both `--mic` and `--timegrapher` for optical-only replay. To reproduce the
saved acoustic windows, build the CLI from commit `8002cdc` in a separate checkout
with `cargo build --release --locked -p timegrapher-cli`. The saved analyzer JSON
records the full available build provenance. Running a newer analyzer is a new
comparison; it must not replace the frozen blind predictions or historical windows.

## What is reproduced

`reproduce.py` decodes the 2–4, 10–12 and 18–20 second excerpts, fits the rim,
measures arm-boundary profiles near reversals, interpolates the endpoint locations
and calculates both boundary amplitudes for eight oscillations per excerpt.
It verifies every resulting amplitude against `../corrected-endpoints.json` with
a 0.1° numerical replay tolerance. That tolerance checks computational
reproducibility, **not physical measurement accuracy**.

`../refit.json` preserves the pre-audio motion-fit seeds that select the search
windows and rotation branch. The script remeasures edge positions from pixels;
it does not re-run the exploratory global search or automatically prove the
360° rotation-count choice. That choice must be reviewed in the intermediate
frames. The script is specific to this crop, geometry and specimen.

The optional acoustic replay cuts the mic at 2.284 s, retains 21.873333 s and
runs the normal CLI with `--bph 28800 --lift 50 --windows ... --json`. It does not
implement another acoustic estimator. Compare its `aligned-windows.csv` with the
saved file in the parent directory. The JSON differs in input/output paths.

To inspect the synchronization independently:

```sh
python inspect_sync.py --video /path/to/IMG_5824.MOV \
  --mic /path/to/audio-001.wav --output /tmp/optical-sync
```

This extracts the phone's mono audio, applies a fourth-order 2–12 kHz Butterworth
band-pass with forward/backward filtering, and computes 1 ms RMS envelopes.
Cross-correlation searches a 0–8 s positive mic offset (the interval suggested
by recording timestamps). It lists prominent mic/phone peak pairs within 20 ms
of that offset. The saved pairs are 4.193/6.475, 5.265/7.549 and 7.163/9.447 s.
The peak positions are not precise tap onsets or an independent clock calibration.

## Preserved records

- `../blind-result.json`: initial full-motion estimate and section fits, before audio.
- `../corrected-endpoints.json` and `../endpoint-measurements.csv`: refined,
  still-blind endpoint measurements; precision allowances are discussed in the note.
- `../audio-video-comparison.json`: rounded predictions and later matched audio.
- `../audio-analysis.json`: full-mic analysis; `../aligned-analysis.json` and
  `../aligned-windows.csv`: the aligned replay. Only ephemeral input path strings
  in saved JSON have been reduced to basenames.
- `../original-frame-crops/`: two unscaled RGB crops from the 10 s excerpt,
  decoded with FFmpeg's display rotation and `crop=320:300:150:440`. Frame indices
  23 and 53 are zero-based within that excerpt. No sharpening or image generation.

The figures are frozen illustrations, not regenerated by this replay. The
annotated boundary rays describe interpolated endpoint estimates overlaid on
nearby sampled frames. Small differences between a line and the sampled frame
are expected. Practical ± allowances have not undergone statistical coverage
validation; they are not suitable as automated pass/fail thresholds.
